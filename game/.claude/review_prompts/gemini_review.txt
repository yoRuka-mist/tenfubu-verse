## 変更概要
カードゲームAIの「先読み」機能の設計。現在のAIは現在の盤面状態のみを見て判断しているが、超進化で得られるカードやスペルダメージを考慮したリーサル判定ができない問題がある。シミュレーション方式で解決する設計。

## 設計書内容

# AI先読み機能（Lookahead System）設計書

## 1. 概要

### 1.1 現状の問題
1. 超進化で得られるカードが計算されない（盞華超進化 → 0コストスペル3枚）
2. リーサル計算が不完全（盤面攻撃力のみ、手札スペル・進化ボーナス未考慮）
3. 行動順序の最適化ができない

### 1.2 解決方針
「仮想的にアクションをシミュレーションする」レイヤーを追加し、最適な行動順序を計画する。

## 2. 設計

### 2.1 アーキテクチャ
- AI Turn Manager: 現在の状態を取得、ActionPlannerでシミュレーション、計画に従って実行
- ActionPlanner: simulateAction, calculateLethalPotential, planOptimalSequence, evaluateBoardState
- SimulatedState: 仮想的な盤面/手札/PP/EP/SEP状態

### 2.2 データ構造
```typescript
interface SimulatedGameState {
    aiHand: SimulatedCard[];
    aiBoard: SimulatedCard[];
    playerBoard: SimulatedCard[];
    playerHp: number;
    aiHp: number;
    aiPp: number;
    aiEp: number;
    aiSep: number;
}

interface SimulatedCard {
    id: string;
    instanceId: string;
    name: string;
    cost: number;
    type: 'FOLLOWER' | 'SPELL';
    currentAttack: number;
    currentHealth: number;
    canAttack: boolean;
    canEvolve: boolean;
    hasEvolved: boolean;
    passiveAbilities: string[];
    hasBarrier: boolean;
    evolveEffects?: SimulatedEffect[];
    superEvolveEffects?: SimulatedEffect[];
    superEvolveGeneratesCards?: string[];
}

type ActionType =
    | { type: 'PLAY_CARD'; cardIndex: number; targetId?: string }
    | { type: 'EVOLVE'; boardIndex: number; useSuperEvolve: boolean; targetId?: string }
    | { type: 'ATTACK'; attackerIndex: number; targetIndex: number; isLeader: boolean }
    | { type: 'END_TURN' };

interface LethalInfo {
    canLethal: boolean;
    requiredActions: ActionPlan[];
    totalDamage: number;
    wardsToRemove: SimulatedCard[];
    damageBreakdown: { boardDamage: number; spellDamage: number; evolveDamage: number; };
}
```

### 2.3 主要関数
- createSimulatedState(): ゲーム状態から軽量シミュレーション状態を作成
- simulateAction(): アクションを仮想実行
- calculateLethalPotential(): リーサル可能性を計算
- planOptimalSequence(): 最適行動順序を計画

## 3. 実装計画
- Phase 1: データ構造とユーティリティ
- Phase 2: シミュレーション関数
- Phase 3: リーサル計算
- Phase 4: 行動計画と統合

## 4. 設計上の考慮事項
- パフォーマンス: 軽量構造体、探索深度制限（5-6手）、早期枝刈り
- 正確性トレードオフ: 主要効果のみ対応、ランダム効果は最悪/最良/平均で評価
- 既存コード整合性: 新規関数追加、HARD難易度のみ、段階的有効化フラグ
- 拡張性: カード定義から効果を読み取る汎用的仕組み

## 5. 設計理由
- シミュレーション方式: 汎用的、新カード追加にも対応しやすい
- 軽量構造体: フルGameStateは巨大、1ターンに数十回シミュレーション可能性
- HARD難易度限定: 人間らしいミス、計算コスト削減、バグリスク低減
