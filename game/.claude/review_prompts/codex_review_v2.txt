# AI先読み機能（Lookahead System）設計書

## 0. 設計変更履歴
### 2026-01-24: 初版 → v2（トリプルレビュー対応）
**変更前**: 抽象的な設計のみ
**変更後**: 具体的な仕様を追加（Ward/バリア処理、コスト管理、探索戦略、評価関数）
**変更理由**: Codex/GLM-4.7からのブロッキング指摘（6件）への対応

## 1. 概要
### 1.1 現状の問題
1. 超進化で得られるカードが計算されない（盞華超進化 → 0コストスペル3枚）
2. リーサル計算が不完全（盤面攻撃力のみ、手札スペル・進化ボーナス未考慮）
3. 行動順序の最適化ができない

### 1.2 解決方針
「仮想的にアクションをシミュレーションする」レイヤーを追加し、最適な行動順序を計画する。

### 1.3 スコープ制限（v1）
- **対応範囲**: リーサル計算のみ（盤面制圧は既存ロジック）
- **探索深度**: 最大6アクション（1ターン内）
- **対応効果**: DAMAGE, AOE_DAMAGE, DESTROY, GENERATE_CARD, SUMMON
- **除外**: 複数ターン先読み、相手の行動予測

## 2. 設計
### 2.2 データ構造
- SimulatedGameState: aiHand, aiBoard, playerBoard, HP, PP/EP/SEP, aiEvolveCount(上限2), aiGraveyard
- SimulatedCard: id, instanceId, cost, type, attack, health, passiveAbilities, hasBarrier, hasAura, necromanceRequired
- ActionType: PLAY_CARD, EVOLVE, ATTACK, USE_SPELL, END_TURN（全てinstanceIdで統一）
- LethalInfo: canLethal, requiredActions, damageBreakdown(board/spell/evolve/storm), resourceUsage

### 2.4 Ward/バリア/攻撃制限の処理仕様
- 守護チェック: STEALTHでない守護のみ有効、守護がいれば守護のみ攻撃可能
- バリア処理: ダメージ0、バリア消費
- 必殺処理: ダメージを与えれば即破壊

### 2.6 探索戦略と枝刈り
- アルゴリズム: 貪欲法 + DFS
- 枝刈り条件: 期待ダメージ不足、リソース不足、攻撃可能フォロワー0、守護未突破、重複状態
- 1手の定義: 1つのActionTypeの実行
- 最大6手: 典型的リーサル5-6手、計算量O(10^6)

### 2.7 コスト管理ルール
- PP: カードコスト消費、回復なし
- EP: 通常進化1消費
- SEP: 超進化1消費
- 進化回数: 上限2回/ターン

### 2.8 ランダム効果の評価方針
- リーサル判定: 最悪ケース
- 除去判定: 期待値

## 3. 実装計画
Phase 1: データ構造とユーティリティ
Phase 2: リーサル計算（簡易版）← 順序変更
Phase 3: シミュレーション関数（コア）
Phase 4: 探索最適化
Phase 5: 行動計画と統合

### 3.1 既存コードとの統合アーキテクチャ
- 呼び出し箇所: executeAiTurn()の先頭
- 条件: HARD難易度 && aiLookaheadEnabled
- フォールバック: リーサル不可時は既存ロジック

## 4. 設計上の考慮事項
### 4.4 拡張性
効果定義方式: カードIDに対応するシミュレーション関数をマッピング
```typescript
const CARD_EFFECT_SIMULATORS: Record<string, (state, card) => SimulatedGameState> = {
    'c_senka_knuckler': simulateSenkaSuperEvolve,
    's_backhand_smash': simulateBackhandSmash,
};
```

### 4.5 エラーハンドリング
- 事前検証: canPerformAction()
- エラー時: 既存ロジックにフォールバック

## 7. 段階的有効化方針
- v1.0: リーサル計算（簡易版）
- v1.1: シミュレーション（基本）
- v1.2: 探索最適化
- v2.0: 全機能有効
